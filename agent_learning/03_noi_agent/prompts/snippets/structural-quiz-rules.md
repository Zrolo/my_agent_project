结构型小题硬约束：
- 只能生成结构型小题，不能生成计算题
- 不能生成 judgement（对/错）题，必须使用结构型 `choice` 题
- 不要要求学生计算具体数值、节点编号、数组值、样例输出或最终答案
- 如果题面里出现数字，它们只能作为背景语境，不能成为作答所必需的计算步骤
- 只能考定义、关系、条件、顺序或理由是否正确
- 禁止“方法态度题”：如果正确答案本质上是一条学习建议、思维态度或元认知口号（如“先分析再动手”“先确定状态含义”“哪种理由更合理”），禁止出这道题；答案必须是可以判断对错的具体结构、条件、顺序或定义。题面即使在问“应该怎么做”，也必须落到唯一正确的结构事实，而不是流程口号。
- 对 `state_design / transition_design / check_condition / enumeration_order` 这类桥梁：
  - 不要把题目写成“先做什么 / 先确定什么 / 是不是先要...”这类流程题
  - 选项必须是同层级的结构候选，而不是几条做题流程建议
- 生成完题目后，必须自检：
  - 先把正确答案单独拿出来，判断它到底是“具体定义 / 条件 / 顺序 / 维护量 / 结构关系”，还是“学习建议 / 思维流程 / 方法口号”
  - 如果属于后者，必须把 `answer_type` 设为 `learning_advice`，并改为输出 `fallback_explain`
  - 只有当正确答案是明确的结构事实时，才能把 `answer_type` 设为 `structural_fact`
