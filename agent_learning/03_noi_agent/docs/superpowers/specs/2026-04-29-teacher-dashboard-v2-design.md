# 教师端 v2：学习诊断与教师干预工作台设计

## Summary

教师端 v2 的目标不是继续堆功能，而是把教师每天带班需要的判断链路做清楚：

1. 哪些学生今天需要关注。
2. 为什么需要关注。
3. 证据来自哪段 AIChat、复盘、验证或反馈。
4. 老师下一步应该怎么介入。
5. 介入后学生是否有改善。

本轮设计采用“先学生档案、后班级聚合”的顺序。第一版不急着做完整班级大屏，而是先把单个学生的学习诊断做准，允许教师修正 AI 标签；等标签质量经过抽查后，再开放班级层学习问题分布。

## Design Principles

- 教师端面向教学动作，不面向系统内部运营。
- 首页只展示稳定、可解释、可行动的信息。
- AI 生成的学习标签必须带证据、置信度和教师修正入口。
- 班级聚合不能先于标签校准上线。
- 复盘必须服务迁移，不只是生成总结。
- 系统维护能力进入高级页，普通教师日常入口不展示内部工程术语。

## Navigation

教师端导航调整为：

- 首页：今日带班。
- 学生：班级学生总表，进入学生档案。
- 账号：学生账号创建、批量创建、重置密码、停用启用。
- 复盘：全部复盘记录与复盘质量。
- 复核：待教师确认的复盘、验证和异常记录。
- 公告：学生首页公告发布。
- 反馈：学生教学反馈。
- 高级：系统维护，仅管理员或维护者使用。

学生档案不作为单独导航项，从学生页进入。

## Data Model

### Cognitive Difficulty

认知困难轴表示学生主要“不懂什么”。第一版由 LLM 给出，但只在学生档案层展示，不直接用于班级聚合。

- `problem_understanding`：题意理解困难。
- `method_selection`：方法选择困难。
- `knowledge_transfer`：听过知识但不知道如何落到题。
- `implementation`：代码实现困难。
- `debugging`：调试定位困难。
- `boundary_edge_cases`：边界或特例困难。
- `complexity_analysis`：复杂度分析困难。

每条认知困难标签必须带：

- 分类标签。
- 证据句。
- 置信度：高 / 中 / 需确认。
- 教师修正状态。

### Session State

过程状态轴表示学生“流程走到哪”。第一版优先用行为规则判断，不依赖 LLM。

- `in_progress`：正常推进中。
- `stuck_unclear`：卡住且说不清。
- `advanced_but_unverified`：已经推进但未验证。
- `verified_passed`：验证通过。
- `verified_failed`：验证未通过。
- `review_completed`：完成复盘。
- `needs_teacher_followup`：建议老师看一下。

### Label Confidence

认知困难标签使用三次独立 LLM 判断做投票：

- 3 次一致：高置信。
- 2:1：中置信。
- 三次都不同：需教师确认。

模型自报置信度不作为主要依据。

### Teacher Correction

学生档案中每条 AI 标签旁提供“改一下”入口。教师可以修改认知困难类型，并可填写一句备注。教师修正结果保存为后续校准样本。

上线两周后随机抽查 30 条：

- 一致率 ≥ 80%：允许上线班级认知困难聚合。
- 一致率 70%-80%：继续只在学生档案层展示。
- 一致率 < 70%：调整分类 prompt 后重新观察。

## Home Page

首页是“今日带班看板”，不展示系统规则运营内容。

### Modules

1. 今日优先看
   - 只展示红色层级学生，最多 5 人。
   - 每条包含学生、触发原因、证据来源、建议动作。

2. 待处理数量
   - 待复核。
   - 学生教学反馈。
   - 复盘生成失败。
   - 未完成验证。

3. 稳定趋势
   - AIChat 活跃人数。
   - 结束验证完成人数。
   - 复盘完成人数。
   - 默认近 30 天。

4. 公告状态
   - 当前置顶公告。
   - 是否存在草稿。

### Not Shown On Home

首页不展示：

- 知识子域分布。
- 认知困难班级聚合。
- 转正规则建议。
- 人工规则登记簿。
- resolver / patch / route / registry。
- prompt / guard / 模型异常观察。

这些进入高级页，或在标签校准后再进入班级分析区。

## Attention Pool

待关注池必须分层，避免提醒疲劳。

### Red

今天优先处理，满足强触发条件之一：

- 结束验证连续失败 ≥ 2 次。
- 同一道题 AIChat ≥ 10 分钟且状态仍为 `stuck_unclear`。
- 学生明确反馈“看不懂 / 不会用”。
- 复盘被系统或教师标记为需要介入。

### Yellow

看一眼，满足弱触发条件之一：

- AIChat 已推进但未做结束验证。
- 复盘已提交但未完成迁移小题。
- 近 7 天只问 AIChat，没有验证或复盘。
- 同类题反复出现相同认知困难。

### Green

正常推进或已通过验证。

每条提醒必须包含：

- 触发原因。
- 证据。
- 建议动作。
- 教师反馈：已处理 / 暂不处理 / 提醒不准。

如果某类提醒两周内多次被标记“不准”，需要下调权重或调整阈值。

## Student List

学生页是班级学生雷达表，不处理账号创建。

每行显示：

- 姓名 / 账号。
- 最近活跃时间。
- 最近题目。
- 最近 AIChat 认知困难。
- 最近过程状态。
- 最近验证结果。
- 最近复盘状态。
- 当前层级：红 / 黄 / 绿。
- 操作：看档案 / 看 AIChat / 看复盘。

筛选：

- 只看红色。
- 只看黄色。
- 只看 AIChat 活跃但未验证。
- 只看复盘未完成。
- 只看最近 7 天无学习记录。
- 按题目标签筛选。
- 按认知困难筛选。

## Student Profile

学生档案是 v2 的核心页面。

### Top Summary

档案顶部必须有不超过 3 行的自动摘要：

> 最近 7 天最值得关注的是：他在「方法选择」上反复停住。  
> 证据：P1119 中把每次询问跑 Dijkstra 当成主方案，经过复杂度对比后才转向 Floyd。  
> 建议：下次课让他口头比较一次“多次查询”场景下预处理和单次查询的区别。

### Sections

1. 当前状态
   - 红 / 黄 / 绿。
   - 最近活跃。
   - 当前建议动作。

2. AIChat 学习观察
   - 认知困难标签。
   - 过程状态。
   - 证据句。
   - 置信度。
   - 教师修正按钮。
   - 建议追问。
   - 可展开原始对话。

3. 结束验证记录
   - 验证题。
   - 学生回答。
   - 判定结果。
   - 错误原因。

4. 复盘记录
   - 最近复盘题目。
   - 复盘是否完成。
   - 迁移小题结果。
   - 可展开详情。

5. 教师备注
   - 老师记录下次要问的问题。

## Account Page

账号页只处理账号生命周期，不展示学习分析。

功能：

- 单个创建账号。
- 批量创建账号。
- CSV / 粘贴表格导入。
- 重置密码。
- 停用 / 启用。
- 搜索账号。
- 导出创建结果。

## Review Page

复盘页从历史列表改为“错题复盘质量页”。

列表字段：

- 学生。
- 题目。
- 题目类型 / 标签。
- 复盘状态。
- 是否完成迁移验证。
- 是否需要教师介入。
- 最近更新时间。

复盘详情固定为：

1. 这类题在考什么
   - 先讲同类题共性，再回到当前题。

2. 我原来哪里没想清
   - 来自 AIChat 摘要或学生填写。
   - 不使用“卡点”作为用户可见词。

3. 旧想法 vs 正确想法
   - 必须并排出现。
   - 不能只写正确想法。
   - 自我解释只挂在差异点上，不要求整篇解释。

4. 这题真正要记住的关键
   - 可以结合题解，但不能变成完整长题解。

5. 下次遇到同类题怎么开始
   - 给可迁移策略。

6. 迁移小题
   - 同类不同情境。
   - 难度略低于原题。
   - 不做纯复述题。

## Human Review Center

复核页是教师确认中心。

复核对象：

- AI 生成复盘质量不确定。
- quiz 判分不确定。
- 学生连续失败。
- 学生反馈看不懂。
- 复盘生成失败。

复核卡片展示：

- 学生。
- 题目。
- 触发原因。
- AIChat 摘要。
- 复盘概况。
- 验证结果。
- 系统建议。
- 教师操作。

教师操作：

- 通过。
- 退回修改。
- 标记需要当面讲。
- 暂不处理。
- 提醒不准。

不展示内部字段：bridge route、resolver、registry、rule id、patch draft。

## Announcements

公告页支持：

- Markdown 编辑。
- Markdown 预览。
- 发布 / 保存草稿。
- 最近公告。
- 置顶公告。

公告类型：

- 本周训练重点。
- 比赛提醒。
- 推荐题单。
- 复习提醒。
- 班级共性问题讲解。

学生首页只展示最近 1-3 条。

## Feedback

反馈页分流为教学反馈和产品问题。

教师默认看到教学反馈：

- AIChat 答得不好。
- 复盘看不懂。
- quiz 不合理。
- 学生说学不会。

产品问题进入高级页或系统维护：

- 页面 bug。
- 题目读取失败。
- 代码运行失败。
- 登录问题。

## Advanced Page

高级页仅管理员或维护者使用。若当前没有管理员角色，入口放在教师端最底部，并标注“系统维护”。

高级页包含：

- 转正规则建议。
- 人工规则登记簿。
- 知识域原始统计。
- 模型异常。
- prompt / guard 观察。
- 生成失败记录。
- resolver / patch 草稿。

## Implementation Order

### Step 1: Information Architecture

- 首页移除内部功能。
- 拆出账号页。
- 新增高级页。
- 教师导航改成教学动作导向。

### Step 2: Student Profile And Diagnosis

- 学生档案顶部 3 行摘要。
- AIChat 观察加入认知困难轴。
- 过程状态轴用行为规则。
- LLM 三次投票。
- 教师修正按钮。

### Step 3: Review And Human Review

- 复盘改成“同类题共性 + 旧想法 vs 正确想法 + 迁移小题”。
- 复核改成教师确认中心。
- 内部字段移到高级页。

### Step 4: Class Aggregation

上线前置条件：

- 运行两周。
- 抽查 30 条。
- 一致率 ≥ 80%。

通过后再开放：

- 班级认知困难分布。
- 知识标签趋势。
- 更细的待关注池统计。

## Acceptance Criteria

- 老师打开首页 30 秒内知道今天先看谁。
- 老师点进档案 30 秒内知道为什么要看。
- 每条 AI 判断都有证据句。
- 教师可以修正 AI 标签。
- 首页不出现内部系统术语。
- 复盘包含“旧想法 vs 正确想法”。
- 复盘后的验证题是迁移题，不是纯复述题。
- 待关注池分红黄绿，不一次性堆出大量提醒。
- 班级聚合必须在标签抽查通过后上线。
- 账号管理不混学习分析。
- 高级页承接系统维护功能。

## Non-Goals

- 第一版不做完整班级认知困难聚合。
- 第一版不做黑箱学习分数。
- 第一版不做复杂预测模型。
- 第一版不把系统维护功能暴露给普通教师首页。
- 第一版不要求人工大规模标注。
