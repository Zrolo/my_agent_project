# Teacher Learning Radar V2 Design

## Goal

教师端不做数据墙，而是每天回答三件事：今天先看谁、班级最近具体卡在哪、老师下一步怎么帮。核心指标从“AIChat 用了多少次”转成“学生是否正在从 AI 支架走向独立解题”。

## Design Principles

- 学生自报不是事实，只是一条待交叉验证的线索。
- 自主完成不做排行榜，只做近 7/15/30 天支架撤离趋势。
- 班级问题必须从大类落到“知识点 + 教学切片 + 涉及学生 + 建议讲法”。
- 小验证不是唯一标准，而是理解证据之一。
- 教师干预记录只做过程闭环；第一版不声称干预有效，避免简单前后对比带来的回归均值误判。

## Student Completion Record

学生端新增“记录这题完成情况”。记录内容：

- 当前题号、题目标题、题目链接。
- 学生自报完成方式：自己做出来、少量提示后做出来、AIChat 帮助后做出来、看题解后补完、还没完全确定。
- 结果：AC、样例通过还没提交、还不确定。
- 一句话总结：这题最关键的一步是什么。
- 系统推断字段：根据 AIChat 轮数、结束验证、总结内容长度等生成可信度与支架类型。

教师端展示时必须写明“学生自报”和“系统判断”，不能把自报直接当成独立完成。

## Attention Pool

教师端首页“今天先看谁”按学生聚合，状态分四类：

- 优先关注：结束验证失败、同类问题反复、AIChat 多轮无推进、复盘或验证暴露明显误解。
- 建议看看：AIChat 使用较多但没有验证，或支架依赖明显。
- 正在独立推进：近 7/15 天有完成记录，总结质量和验证证据正常，AIChat 依赖下降。
- 数据不足：AIChat、完成记录、复盘、验证都少，系统无法判断真实学习状态。

每个学生卡片必须包含原因、证据和老师下一步动作。

## Class Problem Slices

班级主要问题不只显示“方法选择困难”等大类。每条问题至少包含：

- 大类：题意理解、方法选择、知识迁移、代码实现、调试定位、边界特例、复杂度分析、表达不清。
- 知识点/题型：例如 Floyd、二分答案、并查集、树直径、DP 状态设计。
- 教学切片：例如“不理解按时间逐步加入中转点”。
- 涉及学生与分母：例如 5/12 人。
- 建议讲法：老师可以怎么讲这一小段。

首页只显示达到阈值的切片。v1 阈值：同一切片至少 3 名学生，否则放到详情或学生档案。

## Teaching Suggestions

LLM 生成最多 3 条本周教学建议。每条固定包含：

- 建议讲什么。
- 为什么值得讲。
- 怎么讲到可操作粒度。
- 对哪些学生有效。
- 证据。

v1 可先用规则和现有学习问题统计生成稳定文案，后续接 LLM 聚合。

## Rollout

第一阶段：

- 新增完成记录 API 和学生端入口。
- 学生首页显示完成记录与支架撤离提示。
- 教师首页加入今天先看谁、理解证据、教学建议的中文框架。
- 教师学生页展示学生姓名/账号、完成记录、系统判断和老师下一步动作。

第二阶段：

- 建立常见知识点教学切片种子库。
- LLM 只在种子库基础上归纳最多 3 条教学建议。
- 未分类切片进入人工整理队列。

第三阶段：

- 教师干预闭环记录“已处理/暂不处理/判断不准确”等反馈。
- 保留“建议关注但暂不处理”作为自然对照数据，后续论文分析时避免只做单组前后对比。
