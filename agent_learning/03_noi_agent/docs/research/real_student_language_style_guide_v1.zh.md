# 真实学生提问语言风格指南 v1

本文档记录 Research v1 中真实线上学生提问的语言风格观察，用于后续编写 synthetic-but-grounded case、`recent_dialogue`、盲评表上下文和论文数据说明。

它不是学生原始日志公开稿。真实日志只用于本地风格归纳和候选 case 筛选；公开材料应使用脱敏、改写或合成示例。

## 使用边界

- 可用于：生成 held-out case 的 `student_message`、`recent_dialogue`、代码片段场景、教练复核表说明。
- 不用于：直接公开真实学生原文、公开历史 AI 回复、声称合成问题是学生真实原话。
- 论文表述应使用：`synthetic-but-grounded student questions inspired by anonymized real AIChat usage patterns`。
- 中文论文表述应使用：`基于真实 AIChat 使用模式归纳并合成的题面驱动学生问题`。

## 真实学生常见表达特征

真实学生提问通常不像标注表，也不像完整教案。常见特征如下：

1. 很短，默认 AI 知道上下文
   例：`这题为什么要二分？`、`然后怎么处理强连通分量之间的边？`

2. 缺主语、缺完整背景
   例：`这里从哪转？`、`mid 满足改哪边？`、`这个为什么对？`

3. 常用口语疑问词
   例：`为什么`、`怎么`、`到底`、`该不该`、`从哪`、`能不能`。

4. 会给半成型思路
   例：`我第一反应是树的直径，但为什么能用我不知道。`

5. 会贴代码或伪代码，但说明很少
   例：贴一段循环、`check()`、线段树 `update()`，然后只问：`这里为什么错？`

6. 会表达不确定，而不是抽象分类
   例：`样例能看懂，但自己不会推。`、`我总是写反。`

7. 长对话通常是逐步变具体
   不应一开始就写三四句结构完整的自我诊断；更自然的是先说“看了题但不知道从哪开始”，经 AI 追问后变成具体卡点。

## 不合格写法

下面这些写法不适合作为学生问题或近期对话：

- `学生知道可能要记录中间结果，但说不清...`
- `缺少把题面对象和状态语义对应起来的关系。`
- `我想获得可迁移的概念关系。`
- `请通过一个观察问题让我理解当前关系。`
- `我当前卡在状态表示桥。`
- `我希望你不要泄露 critical bridge。`
- 每一条都写成：`这题状态到底该记录什么？`
- 每一条 `recent_dialogue` 都写成：`题意基本能复述，但还没有完整做法。`

这些句子像标注员、论文作者或系统 prompt，不像真实学生。

## 学生问题长度分布

50-case held-out draft 采用以下长度配额：

| 长度 bucket | 数量 | 目标风格 |
| --- | ---: | --- |
| short | 20 | 一句话短问，常缺上下文 |
| medium_short | 15 | 一句话加轻微解释 |
| medium_long | 10 | 说明已有思路和具体卡点 |
| long | 5 | 多句描述，通常来自多轮追问或卡很久的学生 |

短问题不是低质量问题。在线 AIChat 中，学生经常不愿意输入长篇解释；短问也可以有诊断价值。

## 常见短问模板

这些模板可以作为生成器风格参考，但不应机械重复。

| 桥梁类型 | 更像学生的短问 |
| --- | --- |
| 状态/表示语义 | `这个状态怎么想？`、`dp 这一格是啥意思？`、`数组里到底存什么？` |
| 转移/递推来源 | `这里从哪转来？`、`这一步怎么递推？`、`当前格怎么算？` |
| 判定/check | `这题为什么要二分？`、`check 该判什么？`、`true 表示可行吗？` |
| 边界/循环顺序 | `mid 满足改哪边？`、`最后取 l 还是 r？`、`循环为啥倒着来？` |
| 建模/对象关系 | `这题怎么建模？`、`哪些东西当点？`、`这个限制怎么连边？` |
| 贡献/差分/前缀 | `贡献加到哪里？`、`这里怎么打标记？`、`差分减在哪？` |
| 数据结构语义 | `这个结构维护什么？`、`query 查出来是啥？`、`lazy 到底表示啥？` |
| 正确性/不变量 | `贪心为什么对？`、`会不会有反例？`、`排序依据凭什么？` |
| 实现边界 | `初始化怎么设？`、`下标从几开始？`、`int 会不会爆？` |
| 调试证据 | `WA 怎么找反例？`、`样例过了还错。`、`该打印哪个变量？` |
| 直接要答案/代码 | `直接给代码行吗？`、`完整题解发我。`、`能直接告诉答案吗？` |

## recent_dialogue 写法

`recent_dialogue` 的目标是模拟上一两轮自然上下文，不是替学生提前完成诊断。

### 短上下文

推荐 3 行左右：

```text
学生：这题我读完了，但还没开始写。
AI：先别急着写代码，告诉我你现在不确定哪里。
学生：check 该判什么？
```

### 长上下文

推荐 5 行左右：

```text
学生：我看了题面，样例大概能跟。
AI：你先说已经想到哪一步，我再接着问。
学生：我有个贪心想法，但怕是假的。
AI：那先抓一个最不确定的点，不用一次讲完整题解。
学生：样例看起来对，可我不知道怎么证明这个策略一定对。
```

### 不要这样写

```text
学生：我知道可能要记录中间结果，但说不清一个格子或状态里的量表示什么。
AI：请指出当前最卡住的一步。
学生：我缺少把题面对象、已处理范围和状态值语义对应起来的表示关系。
```

上面的问题是：学生话术过于标注化，而且最后一行直接复述了 missing bridge。

## 代码场景写法

真实学生经常只贴代码，不一定会解释完整上下文。生成代码场景时可以使用：

```text
bool check(long long x) {
    long long used = 0;
    // 这里不知道 true 应该表示 x 可行还是不可行
    return used <= limit;
}
```

学生问题可以是：

```text
这里 check 返回 true 到底表示啥？
```

注意：代码片段应暴露学生卡点，但不能在题面或对话里提前写出标准答案。

## 与论文数据的关系

本文档支持三个研究目标：

1. 降低 synthetic case 的模板味，避免审稿人质疑样本不真实。
2. 让 held-out case 更接近在线 AIChat 的真实使用场景。
3. 保证不同 baseline 面对的是自然学生问题，而不是专门为某个方法设计的 prompt。

论文中应说明：

> Student turns were synthetic-but-grounded: they were generated from real problem statements and target bridge labels, while their surface style was guided by anonymized real AIChat usage patterns. Historical AI replies were not used as generation inputs.

中文：

> 学生轮次为 synthetic-but-grounded：内容基于真实题面和目标 bridge 标签生成，表层语言风格参考脱敏真实 AIChat 使用模式；历史 AI 回复不作为生成输入。

## 生成器检查清单

生成或修改 held-out case 前，检查：

- 同一 bucket 内 `student_message` 不应重复。
- 不应出现 `学生知道`、`缺少把`、`可迁移`、`当前关系`、`bridge` 等元话语。
- `recent_dialogue` 最后一行应是学生自然卡点，而不是 gold label。
- long 对话应像逐步追问变具体，而不是一次性完整自我诊断。
- 至少一部分 case 应包含代码片段或错误代码场景。
- 合成问题不得声称为真实学生原话。
