# Minimal Sufficient Student Effort Policy v1

本文件记录 Research v1 的一个重要交互现实与设计原则：

```text
学生在线 AIChat 回复通常很短。
```

原因包括：

- 打字成本高，学生不愿意写长解释；
- 学生通常只针对 AI 的问题做最小回应；
- 详细推理需要额外时间，真实对话里常被压缩成几个词、局部判断或一句短句；
- 如果 AI 要求学生写完整表格、完整推导或多步解释，学生很可能放弃、敷衍或直接要答案。

但这不意味着我们追求“越短越好”。更准确的目标是：

```text
最低足够学生努力：学生动作不应比必要更重，但必须有足够认知价值和诊断价值。
```

也就是说，少打字不能等于少思考。一个只让学生机械选 A/B 的问题，即使输入负担低，也可能没有足够教学价值；如果选项本身已经写出关键桥，学生还可能只是猜中，而不是构造出关系。

## 对 Tutor 生成的影响

后续 Tutor prompt 应默认遵守：

- 只问一个问题；
- 下一步优先设计为短生成式回答，例如 `一两个关键词、一个局部判断或一句短句`；
- 慎用选择题，不要为了短回复而把所有问题选择题化；
- 如果使用选择题，选项不能承载关键桥答案，只能比较非关键现象；更适合作为学生卡住后的降级提示；
- 小而明确的问题可以短答加轻确认，不必硬做选项题；
- 关键桥附近优先让学生用短句/关键词表达观察；如果确实使用“现象选项 + 理由选项”，必须追加极短理由，避免学生纯猜；
- 不要求长篇解释；
- 不要求完整表格；
- 不要求多步推导；
- 不要求学生一次抽象完整通用规则；
- 如果需要微型例子，也只让学生完成一个局部观察或短判断。

## 对 Bridge-Oriented Micro-Example 的影响

高质量微型例子不是让学生完成一个复杂小作业，而是设计一个低输入成本的观察点。

较差：

```text
请完整模拟整个数组变化，并总结为什么倒序枚举正确。
```

较好：

```text
只看容量 4：用一句短话说，它现在更像在看“旧的容量 2”还是“刚更新过的容量 2”？再补 3-8 个字说明理由。
```

如果学生卡住，可以降级为低风险选项，但选项不能直接写出最终规则：

```text
只看容量 4，回复一个组合即可：
A. 会用到刚更新过的容量 2
B. 不会用到刚更新过的容量 2
理由：
1. 这个值来自当前轮刚更新的格子
2. 这个值只可能来自上一轮旧格子
你回 A-1 / A-2 / B-1 / B-2 即可。
```

较差：

```text
请列完整表格：每个节点最终被路径经过几次，并写出所有加减标记。
```

较好：

```text
只看节点 2：用“经过/不经过”回答这条路径实际会不会经过它。下一步再看怎么让汇总结果体现这个事实。
```

## 对盲评的影响

`coach_next_step_clarity_score` 需要加入输入成本判断：

- `2`: 下一步明确、具体、负担不超过必要，同时有认知价值和诊断价值；
- `1`: 有下一步，但较宽、较多、略费力、不够具体，或虽然很短但思考价值不足；
- `0`: 没有可执行下一步，或要求长篇解释、完整表格、多步推导。

这个约束不会降低教学目标。它不是鼓励每轮都做短选择题，而是把“让学生思考”改成更符合真实在线对话的短生成形式：

```text
低负担但有信息量的回答 -> AI 继续诊断/确认 -> 学生逐步过桥
```

而不是：

```text
一次性要求学生写完整推理。
```

## 推荐分流

- 小而明确的问题：短答 + 轻确认，不要硬做选择题。
- 概念模糊或关键桥附近：微型例子 + 短生成式观察，让学生少打字但必须判断；卡住后才用不夹答案的选项降级。
- 需要迁移或总结：要求一句短解释，不要求长篇。
- 复盘、训练或学生明确愿意深入：才允许更长解释、完整表格或多步推导。

## 对论文表述的影响

推荐写法：

```text
We optimize for minimal sufficient student effort: the requested action should be no more burdensome than necessary, but still cognitively and diagnostically informative.
```

中文：

```text
我们优化的不是“越短越好”，而是“最低足够学生努力”：学生动作不应比必要更重，但必须有足够认知价值和诊断价值。
```
