# Real AIChat Legacy Context Contamination Screening 20260512

This note records a second screening pass over the 45 recommended real online AIChat candidates. The goal is to check whether old online `current_system` AI replies before the target turn had already shaped the student state, especially by revealing the critical bridge.

## Why This Step Is Needed

Real online conversations are valuable because they contain authentic short student replies, code-debug turns, and multi-turn context. However, the historical AI replies in these logs were generated by the old online system, whose quality is unstable.

Therefore:

- real student questions can be used as candidates;
- old AI replies must not be treated as gold tutor responses;
- old AI replies before the target turn may be used only as `recent_dialogue` context and must be checked for contamination;
- old AI replies after the target turn may be used only as `observed_current_system_response`, not as a reference answer.

## Input

Input file:

```text
recommended_real_aichat_45_for_coach.csv
```

Each candidate contains:

- the target student turn;
- a small context window before the target turn;
- the latest AI reply before the target turn, `context_ai_reply`;
- the old-system AI reply after the target turn, `assistant_reply`.

This pass only checks `context_ai_reply` and earlier assistant context for target-turn contamination. `assistant_reply` is not used to judge student-state contamination because it happens after the target student turn.

## Labels

| Field | Meaning |
|---|---|
| `legacy_ai_context_contamination=none` | No old AI reply context before the target turn |
| `legacy_ai_context_contamination=low` | Old AI context exists but is mostly general guidance, questions, or light scaffolding |
| `legacy_ai_context_contamination=medium` | Old AI context contains partial algorithm concepts, local relations, or stronger hints that may shape the current student wording |
| `legacy_ai_context_contamination=high` | Old AI context may have revealed code, a complete method, exact state definition, recurrence, check semantics, boundary update, or another critical bridge |

Recommended research-use labels:

| `recommended_research_use` | Meaning |
|---|---|
| `main_eval_candidate` | Can enter the real-log main-evaluation candidate pool after manual anonymization and coach review |
| `dev_or_contextual_candidate` | Suitable for dev, error analysis, or robustness; not recommended for headline held-out use |
| `exclude_from_main_eval` | Not recommended for the main experiment; useful as old-system contamination or failure evidence |

## Interpretation Boundary

This screening uses heuristic rules, not final coach judgment. The rules check whether prior AI context contains:

- complete code, pseudocode, complete solution language, or "代码如下";
- exact DP state / transition, check return semantics, boundary update, lazy semantics, or similar critical-bridge completions;
- long old-AI explanations that make the current short student question dependent on the old system;
- general questioning, light hints, or micro-tasks that are less likely to contaminate the student state.

Final inclusion still requires coach confirmation:

- whether old AI context truly changed what the student already knew;
- whether the target student turn can still be independently labeled for missing bridge;
- whether the case can be safely anonymized;
- whether it represents a real competitive-programming tutoring scenario.

## Revision After Subagent Self-Review

On 2026-05-12, an independent GPT-5.5 / xhigh subagent performed a reviewer-style self-review of the real-log screening outputs. Its conclusion was:

- the samples are suitable for coach review, but cannot directly enter the main evaluation in their current form;
- `privacy_status` remains automatic-redaction `needs_manual_review`, so the files are not ready for public sharing;
- the 33 main candidates are category-skewed, with graph/tree, debugging, and implementation-boundary cases dominating, while DP, data structure, and greedy cases are underrepresented;
- `low` contamination cases still require case-by-case coach confirmation and should not be treated as automatically clean;
- old AI context must be auditable in full, not only via the latest AI reply;
- the workbook should not default to `privacy risk = none` or `split = heldout_real_candidate`.

## Student-Only v3 Workbook

Later discussion tightened the use of real-log samples: the main ablation should not feed old online AI replies into new tutor conditions. It should use the real current student question plus necessary problem/code context and coach labels. Historical AI replies are retained only in audit fields for contamination review and legacy-system observation; they are not generation input and are not gold responses.

A student-only v3 coach workbook was generated:

```text
/Users/kongyouli/Downloads/real_aichat_candidate_screen_20260512/real_aichat_student_only_candidate_review_33_20260512_v3.zh.xlsx
```

Key v3 changes:

- added `删除旧AI后是否可理解`; only rows marked `yes` may be exported as main-evaluation candidates;
- `学生当前问题（主消融输入）` is the core input for later baseline generation;
- `目标turn前旧AI上下文（只供审计，不给模型）` and `完整近期对话（只供审计，不给模型）` are for human audit only;
- `目标turn后旧系统回复（baseline观察，非上下文，非gold）` records the old system's observed response only;
- exported `generation_input.recent_dialogue` and `generation_input.context_ai_reply` must be empty;
- historical AI context is retained only under `audit_context` for traceability and contamination review.

Paper wording:

> We use real student questions from online AIChat logs as candidate turns, while historical AI replies are retained only for audit and legacy-baseline observation. They are removed from generation inputs for all new tutor conditions.

## Export After Review

A conversion script has been added:

```bash
python3 -m evals.aichat.export_real_log_candidates_from_review \
  --input /path/to/real_aichat_student_only_candidate_review_33_20260512_v3_filled.zh.xlsx \
  --output-jsonl docs/research/real_aichat_candidate_set_v1.jsonl
```

By default, the script exports only rows with `审查状态=保留主评测` and prevents incomplete or unclean rows from entering the main dataset. It rejects rows where:

- `missing_bridge（教练填）` is empty;
- `forbidden_content（教练填）` is empty;
- `success_criteria（教练填）` is empty;
- `隐私风险` is not `none`;
- `建议split=undecided` or blank;
- `删除旧AI后是否可理解` is blank, `no`, or `uncertain`.
- `是否自包含` is not `yes`;
- `是否需要补充题面/代码上下文` is not `no`;
- `是否近重复样本` is not `no`;
- `是否代表真实卡点` is not `yes`;
- `是否适合主评测` is not `yes`;
- `需重点复判` is not `no`;
- `旧AI上下文污染初筛` is not `none` or `low`;
- `学生当前问题（主消融输入）` is empty;
- `类别` is empty;
- both `题号/URL` and `题目标题` are empty.

The script first looks for the `student_only候选_v3` sheet and falls back to the earlier `候选样本_v2` sheet when v3 is absent.

To inspect per-row rejection reasons before export, create a strict screening report:

```bash
python3 -m evals.aichat.export_real_log_candidates_from_review \
  --input /path/to/real_aichat_student_only_candidate_review_33_20260512_v3_filled.zh.xlsx \
  --output-jsonl /tmp/real_aichat_candidate_preview.jsonl \
  --screen-report-json /tmp/real_aichat_strict_screen_report.json \
  --allow-incomplete
```

Important: `--allow-incomplete` is only for structure preview and screening reports. It must not be used for formal main-evaluation export.

For structure previews only, use:

```bash

```

Outputs created with `--allow-incomplete` must not be treated as main-evaluation data.
