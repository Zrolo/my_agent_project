## focus
- `transition_design`

#### 好例子
- 题面：
  - `如果 dp[j] 表示“容量不超过 j 时能得到的最大价值”，加入当前物品时，下面哪个转移是对的？`
  - `A. dp[j] = max(dp[j], dp[j-w] + v)`
  - `B. dp[j] = dp[j-w] + v`
  - `C. dp[j] = max(dp[j-1], v)`
  - `D. dp[j] = dp[j] + v`
- 为什么好：
  - 直接落到了“转移方程”这个具体结构上，不再是抽象地问“这一步先做什么”
  - 错误选项都对应真实误区：
    - 漏掉不选分支
    - 下标含义混乱
    - 忽略容量限制
  - 学生答对后，老师能比较有把握地认为他至少认出了正确转移结构

#### 坏例子
- 题面：
  - `如果这题卡在转移设计，这一步更该先想清楚什么？`
  - `A. 先把转移式写出来`
  - `B. 先看每一步在比较什么`
  - `C. 先把数组开大一点`
  - `D. 先把样例背下来`
- 为什么坏：
  - 表面上在测转移，实际上还是在测“会不会说老师口号”
  - A/B 都像正确话，学生可能只是猜“更像标准答案”的一句
  - C/D 太假，不能提供有效干扰

#### 好的 distractor_feedback
- 例子：
  - `这个写法漏掉了“不选当前物品”这一支——dp[j] 原来的旧值代表不放当前物品时的最优解，直接覆盖就丢掉了它。`
- 为什么有效：
  - 直接指出学生选中选项错在“哪一支被漏掉”
  - 不是简单说“少了 max”，而是把结构意义说清楚

#### 坏的 distractor_feedback
- 例子：
  - `这个选项不对，请再想想。`
- 为什么无效：
  - 学生不知道自己到底错在哪个结构
  - 对老师也没有诊断价值

#### 老师视角备注
- 这类题最容易误判的是：
  - 学生知道“转移要比较两种情况”，但不一定能在真实题里稳定写出来
- 所以答对后还要看：
  - 是 `main` 就过，还是 `confirm` 后才稳

#### 学生视角备注
- 初中生通常能理解“放当前物品 / 不放当前物品”
- 不太容易理解“当前状态和旧值比较”这种纯术语表达，所以反馈最好带动作词

## focus
- `state_design`

#### 好例子
- 题面：
  - `如果准备用 dp[j]，下面哪种解释更合理？`
  - `A. dp[j] 表示容量不超过 j 时的最大价值`
  - `B. dp[j] 表示已经选了 j 个物品时的最大价值`
  - `C. dp[j] 表示第 j 个物品的价值`
  - `D. dp[j] 表示恰好装满 j 时的方案数`
- 为什么好：
  - 测的是“状态到底表示什么”，而不是泛泛地说“先确定状态”
  - 错误选项很像学生真实会混淆的几种状态含义
  - 题干短，学生容易知道自己在判断什么

#### 坏例子
- 题面：
  - `如果这题卡在状态设计，这一步你更该先确定什么？`
  - `A. 先说清这一维状态到底表示什么`
  - `B. 先把转移式硬写出来，再回头补状态定义`
  - `C. 先把循环顺序定下来，再倒推状态意思`
  - `D. 先把边界和数组大小定死，再看状态够不够`
- 为什么坏：
  - 虽然比最早版本已经好一点，但本质还是元问题
  - 学生还是在选一句“更像老师会说的话”
  - 没有真正让学生去识别状态含义

#### 好的 distractor_feedback
- 例子：
  - `这个定义把“容量”错写成了“物品个数”，会让后面的转移维度全都跟着错掉。`
- 为什么有效：
  - 直接指出混淆的是哪两个对象
  - 让学生知道错的不是术语，而是“维度选错了”

#### 坏的 distractor_feedback
- 例子：
  - `这个状态定义不准确。`
- 为什么无效：
  - 还是老师视角语言，学生听完依然不知道哪里不准确

#### 老师视角备注
- 这类题最容易误判的是：
  - 学生会认状态定义，但不会把它和后续转移接起来
- 所以后续最好配一题 transition 继续验证

#### 学生视角备注
- “状态”“维度”这类词对初中生已经偏抽象
- 如果能直接对照“容量 / 个数 / 价值 / 方案数”，理解会明显更好

## focus
- `general_modeling`

#### 好例子
- 题面：
  - `这道题里如果要建图，下面哪种理解更合理？`
  - `A. 点表示一个位置，边表示从这个位置可以直接走到另一个位置`
  - `B. 点表示答案大小，边表示程序运行顺序`
  - `C. 点表示样例里的数字，边表示输入顺序`
  - `D. 点表示每一行代码，边表示变量赋值关系`
- 为什么好：
  - 虽然仍然是建模题，但已经落到“点/边分别表示什么”
  - 学生不需要先会完整解法，也能判断结构是否合理
  - 适合建模类桥梁作为第一层结构题

#### 坏例子
- 题面：
  - `这一步更该先看清哪件事？`
  - `A. 题目里的对象和它们之间的关系`
  - `B. 先把图建出来，再回头看谁和谁有关`
  - `C. 先想最短路模板怎么写`
  - `D. 先把答案形式猜出来`
- 为什么坏：
  - A 虽然方向对，但太空，学生不知道“对象”和“关系”到底指什么
  - B/C/D 虽然像误区，但仍然停留在抽象层
  - 学生选对后，也很难说明自己已经会建模

#### 好的 distractor_feedback
- 例子：
  - `这个理解把“答案”当成了图里的点，但题里真正会互相连起来的是位置之间的可达关系，不是答案本身。`
- 为什么有效：
  - 把“对象选错”这个建模错误讲清了
  - 学生能知道自己不是不会图，而是“把谁当点”这一步错了

#### 坏的 distractor_feedback
- 例子：
  - `建模方向不对。`
- 为什么无效：
  - 这句话对老师来说像结论，对学生来说几乎没有帮助

#### 老师视角备注
- 这类题最容易看起来具体，实际上还是空
- 一定要检查：
  - 题面里是不是已经把“点/边/关系对象”落到具体名词上

#### 学生视角备注
- “对象”“关系”这两个词很容易过于抽象
- 对初中生来说，最好替换成：
  - `谁和谁`
  - `什么能连到什么`
  - `什么表示点，什么表示边`
