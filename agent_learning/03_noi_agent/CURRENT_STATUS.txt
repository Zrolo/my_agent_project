🎯 我们现在在做什么
  构建一个“错题驱动微课堂”式的 NOI 竞赛教练系统，目标不是只把题讲会，
  而是帮助学生从“等提示”走向“自己开题、自己建路径、自己修正”。

  当前网站主链路：
  - 打卡
  - AI 复盘
  - 主 Quiz
  - Follow-up / Confirm / 补救
  - 老师端证据链

✅ 当前已经稳定的部分

  1. v1.2 主流程状态机
     - Round 1 正确后不再直接结束
     - 会进入 self_check_required
     - 支持：
       - clear
       - guessed -> confirm
       - confused -> remedy

  2. bridge_path 证据链
     - 终态时写入一次 bridge_path
     - 当前枚举包括：
       - main_clear
       - main_guessed_confirm
       - main_guessed_remedy
       - main_confused_remedy
       - followup_correct
       - followup_remedy

  3. 老师端证据展示
     - 能看到学生自评
     - 能看到过桥路径
     - 能看到“老师解读”
     - 能看到轻量“近期重复卡桥”提示

  4. 复盘质量护栏（v1.2）
     - 非 editorial 默认不应直接报算法名
     - 当前先做 detection + logging
     - 命中会记录：
       - algorithm_name_leaked

  5. 结构型 quiz 骨架
     - Batch A 已迁入模板化 prompt 骨架
     - Batch B 第一批已接入：
       - data_type
       - loop_boundary
       - recursion_structure
       - complexity_fit
     - quiz 输出已开始统一为：
       - options 对象数组
       - bridge_feedback
       - distractor_feedback
       - meta.focus / meta.algorithm_category

🟡 当前仍需关注的风险

  1. 真实模型生成质量
     - 当前本地回归主要验证状态机和字段契约
     - 不等同于真实 Kimi/Moonshot 生成质量

  2. 算法名泄漏目前只检测，不自动改写
     - 这是 v1.2 的有意取舍
     - 后续可再讨论是否进入 v1.5 自动重写

  3. 改错落实仍是“轻提示”
     - 目前只有老师端近期重复卡桥提示
     - 还没有完整的“最近 3 座桥”档案层

  4. 强化练习题源还没解决
     - v2 的关键难点不是界面，而是题从哪里来

  5. 真实模型下的结构型题面质量还需抽样联调
     - 本地回归已覆盖 schema 和状态机
     - 但“题面是否够具体”仍需真实页面人工审核
